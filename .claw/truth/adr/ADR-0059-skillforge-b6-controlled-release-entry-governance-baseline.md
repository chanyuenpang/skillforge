# ADR: SkillForge B6 配置与系统能力受控发布入口治理基线

## Status

accepted

## Context

B6 的目标不是宣称“配置与系统能力已经产品化完成”，而是把高影响配置和系统动作收成一条统一的受控发布入口治理链。此前如果继续沿用分散变更与零散门禁，后续就很难稳定解释版本锚点、门禁衔接、锁定修订语义、异常回看和验收口径之间的关系。

## Decision

决定将配置与系统能力的高影响变更统一收口到受控发布入口，并以负责人级规则基线治理，具体包括：

1. 入口对象必须可追溯，且具备明确的状态流转，不再允许把高影响配置/系统动作作为分散变更直接散落执行。
2. 版本锚点与门禁衔接必须进入入口主链，确保变更、校验与放行能在同一条链路上解释。
3. 锁定修订语义必须明确，避免后续在修订、回滚与继续推进时出现歧义。
4. 最小回看槽位必须保留，保证异常可以回看、解释与复盘，而不是事后补写证据。
5. 验收口径与防越界检查必须前置，确保第二阶段总联调、第三阶段入口决策、跨域深联动和智能治理能力不会被提前承诺。

这次收口的核心结果是：配置与系统能力已经形成统一入口治理基线，但仍停留在规则层，不等于真实业务样本下的全链路产品化完成。

## Alternatives Considered

- 继续维持分散变更、按需门禁：被拒绝，因为会让版本锚点和回看路径长期碎片化。
- 直接承诺第二阶段总联调或第三阶段入口决策：被拒绝，因为当前阶段只应先收紧入口治理基线。
- 只记录验收结论，不单列异常槽位与锁定修订语义：被拒绝，因为这样异常难以解释，修订边界也会失控。

## Consequences

- 正向：高影响配置和系统动作不再是分散变更，而是进入统一受控发布入口治理链。
- 正向：版本锚点、门禁、锁定修订语义与回看槽位开始可统一解释，后续异常更容易定位。
- 正向：阶段边界更清楚，避免把第二阶段总联调或第三阶段入口决策提前写进承诺。
- 取舍：当前成果仍停留在规则层，尚未补齐真实业务样本下的全链路验证。
- 风险：如果后续实现再次把入口拆散，治理链会重新碎片化。
- 验证锚点：已完成范围守门、入口对象与状态流、门禁与版本一致性映射、证据可见性与异常槽位、验收口径与防越界检查、文档回写与收口结论的落盘。
