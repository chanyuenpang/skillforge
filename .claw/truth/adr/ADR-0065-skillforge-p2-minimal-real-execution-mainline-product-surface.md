# ADR: SkillForge P2 最小真实执行主线产品面收敛

## Status

accepted

## Context

在第五阶段已经完成最小真实执行闭环与 P1 最小对象链、状态机主干收敛之后，P2 需要把这条主线进一步落到产品面：明确用户如何在产品中完成创建、编排、审批、执行、回看、复盘的最小动作链，并固定运行中心、审批中心与知识资产层的最小职责分工。

如果不在这一层收口，后续实现很容易再次回到只读看板、候选能力展示或文档先行，导致真实执行主线和产品交互面脱节。

## Decision

决定将 SkillForge 第五阶段 P2 的负责人级交付固定为“最小真实执行主线产品面收敛”，并按以下规则推进：

1. 用户侧必须能沿一条最小动作链完成 `创建 / 编排 / 审批 / 执行 / 回看 / 复盘`，且这条链必须能对应到一条真实任务闭环。
2. 运行中心负责承接执行与结果回看，审批中心负责审批门禁，知识资产层负责复盘结果与资产回沉；三者职责必须拆开，不能混成单一平台壳层。
3. 产品面只收敛最小页面 / 模块集合与关键交互，不扩展为大而全平台界面，也不把高阶能力写成已成立的产品事实。
4. P2 产出的锚点文档必须能直接约束后续 P3 与实现层推进，作为产品面、职责边界与冻结项的统一依据。
5. 对于自动回写、自动优化、自动推荐、大规模真实样本和复杂联动能力，继续保持冻结，不在本阶段写成完成态。

## Alternatives Considered

- 继续只做对象链与状态机收敛：被拒绝，因为 P2 的目标已经转向产品面职责与最小交互面。
- 先扩展完整产品壳层再回收边界：被拒绝，因为会让主线再次失焦到“大而全”。
- 仅记录页面清单，不定义职责边界：被拒绝，因为后续实现会缺少可执行的分工锚点。

## Consequences

- 正向：最小真实执行主线的用户动作链被固定，后续实现不容易回到只读或候选展示。
- 正向：运行中心、审批中心、知识资产层的职责边界更清晰，便于后续实现和验收。
- 正向：P2 锚点文档可以直接作为 P3 与实现层的约束输入。
- 取舍：本阶段不承诺自动回写、自动优化或大规模联动能力的解锁。
- 风险：如果后续再次把产品面写成“功能全量图”，主线会重新膨胀。
