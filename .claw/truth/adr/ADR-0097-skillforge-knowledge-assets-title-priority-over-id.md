# ADR-0097: SkillForge 知识资产列表标题优先于 ID 展示

## Status

accepted

## Context

在 `KnowledgeAssetsPage` 里，原先列表主展示偏向 `id`，用户需要先看一串标识才能判断文档用途。计划记录中的用户反馈明确指出：页面已经有文档标题时，列表却仍以 `id` 作为主展示，会让知识资产页面退化成“机器清单”，削弱可读性与检索效率。

本次里程碑的目标不是改变后端协议，而是把知识资产列表的呈现方式改成更符合产品使用习惯的顺序：先让人看懂，再让机器识别。

## Decision

决定将 `KnowledgeAssetsPage` 的列表主展示规则固定为：

1. **主展示优先使用标题类字段**
   - 列表行首优先展示 `title`。
   - 当 `title` 不可用时，再回退到 `name`。
   - 只有在标题类字段都不可用时，才把 `id` 作为兜底展示。

2. **`id` 退为辅助信息**
   - `id` 不再承担用户第一眼识别文档用途的职责。
   - `id` 只保留为辅助列或次级识别信息，用于精确定位，不用于主叙事。

3. **列表语义以人类可读性优先**
   - 列表的排序、回退文案和视觉权重都应服务于“先看懂这是什么文档”。
   - 该规则适用于知识资产列表页的长期展示策略，后续新增同类列表也应默认继承这一优先级。

## Alternatives Considered

- **继续以 `id` 作为主展示**：拒绝。用户无法从编号直接理解文档用途，违背产品化展示目标。
- **只在有标题时才显示标题，其他情况保持原样**：拒绝。回退策略需要统一，否则列表会出现混乱的阅读体验。
- **把标题与 `id` 平权并列展示**：拒绝。首屏注意力会被拆散，无法形成清晰主次。

## Consequences

- 正向：用户可以先通过标题判断文档用途，不必先解码 `id`。
- 正向：知识资产列表与整套 Web UI 的“人类可读优先”风格保持一致。
- 正向：后续新增知识类列表时，有了明确的默认展示顺序。
- 取舍：在标题质量较差的数据场景下，仍需要额外兜底策略。
- 验证锚点：计划中已完成“知识资产列表的人类可读展示”验证，后续变更不应回退到 `id` 主展示。
