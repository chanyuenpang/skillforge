# ADR: SkillForge 网页产品壳层与总览工作台落地为一级导航骨架

## Status

proposed

## Context

当前网页端已经不再是单一“风险审批页”的展示，而是要从“风险审批子域可用”推进到真正的产品壳层阶段：先建立总览工作台、统一一级导航与基础页面框架，再把风险审批放回壳层内作为核心子域之一。

计划明确指出，过去的形态几乎只有一个主页面，这会限制后续子域扩展、入口组织和信息架构稳定性。因此需要先把壳层与总览工作台定下来，避免后续功能继续以“单页特例”方式堆叠。

## Decision

决定将 SkillForge 网页端的下一阶段产品形态收敛为“产品壳层 + 总览工作台 + 多子域导航”的结构，并以此作为后续页面扩展的统一框架：

1. **总览工作台成为一级入口**
   页面入口不再只围绕风险审批展开，而是先提供总览工作台，用于承载多子域入口和全局态势。

2. **统一一级导航与基础页面框架**
   `Layout` 级别的壳层布局承担一级导航、页面骨架和子域承载区，避免每个页面各自定义壳层结构。

3. **风险审批降为壳层内核心子域之一**
   风险审批继续保留，但不再是几乎唯一页面；它应作为壳层中的一个核心子域被访问和组织。

4. **前端路由入口与最小服务层继续作为壳层接入点**
   `App.jsx` 负责路由入口组织，`web-server.mjs` 作为当前最小 web 服务承载层，后续首页与占位入口扩展都应沿这条接入链推进。

## Alternatives Considered

- 继续维持“风险审批单页为中心”的结构：拒绝。这样会让产品继续停留在单一页面阶段，难以容纳后续子域。
- 直接为每个新页面单独扩壳：拒绝。会造成导航与布局分裂，难以形成统一信息架构。
- 先做更完整的业务子域，再补壳层：拒绝。会把基础结构问题延后，导致后续扩展成本更高。

## Consequences

- 正向：后续新增子域可以复用统一壳层，不必重复建设页面外框。
- 正向：总览工作台能成为多个功能入口的统一起点，信息架构更清晰。
- 正向：风险审批不再占据唯一入口地位，产品形态更接近真实工作台。
- 取舍：需要先补齐壳层和导航，短期内不是最“看得见业务结果”的改动。
- 风险：如果总览工作台只做成静态占位而不承接导航规则，容易退化成装饰页。
- 验证锚点：`App.jsx`、`Layout.jsx` 和 `web-server.mjs` 的接入链应持续作为后续首页与占位入口扩展的约束点。
