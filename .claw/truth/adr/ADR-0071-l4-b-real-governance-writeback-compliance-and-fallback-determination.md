# ADR: L4-B 真实治理：回写合规与回退判定

## Status

accepted

## Context

L4-B 这次收口的关键，不是已经完成了真实样本上的回写合规卡与回退判定单产出，而是把首条真实样本所需的治理执行骨架固定下来。计划明确了第一波真实治理范围、回写对象、治理/回退原子任务、依赖顺序、回写合规卡与回退判定单的最小字段、边界规则与阶段禁区；同时把“只写已发生且有证据锚点的事实”与“缺锚点、越界、外推一律回退或禁写”的规则显式固化。

如果不把这些边界收口，后续很容易把“治理骨架已固定”误当成“回写合规卡与回退判定单已经在真实样本上正式产出”，或者把未覆盖的推断、越界信息写进治理结论。

## Decision

决定将 L4-B 的负责人级结论固定为“真实治理执行骨架”，并按以下规则作为后续执行约束：

1. L4-B 第一波只围绕回写对象清单、可写/不可写边界、回退触发条件，以及与 L4-A 裁决/挂账的衔接关系推进。
2. 先固化“只写已发生且有证据锚点的事实”与“缺锚点、越界、外推一律回退或禁写”的规则，再补回退归类与后续消费边界。
3. 治理类任务与回退判定类任务必须拆成原子任务，并明确依赖顺序、并行窗口与合并收口方式。
4. 回写合规卡与回退判定单必须显式固定最小字段与判级规则，避免口头化治理。
5. 阶段边界必须显式冻结：当前完成态是“真实执行骨架”，不是“回写合规卡与回退判定单已经在真实样本上正式产出”。
6. 后续执行应直接接力该骨架，不需要重新发明 L4-B 结构。

## Alternatives Considered

- 直接把 L4-B 解释为真实治理已完整落地：被拒绝，因为计划的 retrospective 已明确这次完成的是骨架收口，不是正式产出。
- 把回写对象、治理规则与回退判定混成单一任务：被拒绝，因为会削弱治理线与回退线的独立性，降低边界校核价值。
- 把越界/无锚点信息也纳入治理结论：被拒绝，因为会破坏“只写已发生且有证据锚点的事实”的治理底线。

## Consequences

- 正向：L4-B 的回写对象范围、`可写/不可写` 边界、回退触发条件、合规卡字段与回退判定单字段被固定，后续可直接接力执行。
- 正向：治理类与回退类原子任务可以直接派发，不必重新发明拆分方式。
- 正向：避免把未完成的真实样本治理误写成已正式产出。
- 取舍：本阶段不进入真实样本上的正式回写产出，推进会更克制。
- 风险：如果后续把“执行骨架”当成“正式产出”，会误判完成度。
- 验证锚点：`plans/subplan-8-subplan-l4b-回写合规与回退判定真实治理.json` 中 tasks 1-3 的 done 记录与 retrospective。
