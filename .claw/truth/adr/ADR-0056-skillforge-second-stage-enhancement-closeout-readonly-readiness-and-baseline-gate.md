# ADR: SkillForge 第二阶段增强收口采用“先验证密度、后进入更深能力”的门禁策略

## Status

accepted

## Context

SkillForge 第二阶段不是直接进入写操作、深治理或深编排，而是先把第一阶段的可演示面补成可复现、可回归、可托底。

在这次收口前，运行中心只完成了非空样本构造路径的侦察，还没有真正构造样本；知识资产 `skill-fixture` 分支则已经完成命令级抽测；阶段一轻量回归基线也已经固化到 `.claw/truth/skillforge-阶段一回归基线.md`。这说明第二阶段的关键问题不是继续扩功能，而是先把验证密度和回归门禁补齐。

## Decision

决定将第二阶段增强收口策略固定为：**先补阶段一增强项，确认回归基线，再允许进入更深能力建设**。

具体规则如下：

1. **运行中心非空样本必须先按最小方案实构**
   仅完成构造路径侦察不算进入下一步；后续首动作应是完成一次真实样本构造，并据此做最小回归核验。

2. **`skill-fixture` 分支以命令级抽测作为已验证门槛**
   `skill-fixture` 只要完成稳定的命令样例验证，就可以从“待验证”升级为“已验证”，但这不自动等同于全量回归完成。

3. **阶段一轻量回归基线作为后续增强的对照标准**
   后续所有增强与入口判断，都必须以 `.claw/truth/skillforge-阶段一回归基线.md` 作为最小回归基线。

4. **未完成样本实构前，不进入更深写操作或治理能力**
   在运行中心非空样本未真正构造并核验前，不应贸然进入更深能力建设，以避免把“路径清晰”误当成“能力已落地”。

## Alternatives Considered

- 直接进入写操作、资产治理或更深编排：被拒绝，因为会跳过当前阶段的验证缺口，破坏可回归基线。
- 只记录运行中心路径侦察结果而不建立基线：被拒绝，因为没有回归对照面，后续增强无法稳定判断是否回退。
- 把 `skill-fixture` 抽测当成全量完成：被拒绝，因为命令级验证只能证明分支可用，不能替代完整回归。

## Consequences

- 正向：第二阶段入口从“继续扩功能”改为“先补验证密度”，可显著降低阶段漂移风险。
- 正向：`skill-fixture` 分支从“代码实现”升级为“已验证”，减少后续对该分支的重复侦察成本。
- 正向：`skillforge-阶段一回归基线.md` 成为后续增强的明确对照面，增强动作更容易判断回退。
- 取舍：运行中心非空样本尚未真正落地，下一阶段首动作被明确约束为样本实构与回归核验。
- 风险：若未来绕过基线直接推进深能力，可能再次把演示态误当成稳定态。
