# ADR: Milestone O 真实任务接入与 SkillForge 默认流程融合

## Status

proposed

## Context

上一阶段已经完成规则层与 workflow 的落地验证，本阶段不再做拟真实验，而是把 SkillForge 正式嵌入真实项目任务推进中，作为默认中间层使用。

在这种推进方式下，真实任务进入后需要先写任务意图，再 review plan，回写计划，优化 subagent prompt，最后派发执行，并在结果回流中持续优化接口与产品面。这样做的目的不是继续单独验证工具，而是让工具在真实任务里暴露问题、沉淀规则、收敛接口，并把网页端可观测性、真实业务接入边界、计划评审与 prompt 优化统一到同一条负责人默认工作流中。

## Decision

后续真实任务推进默认采用 SkillForge 中间层，不再把工具验证与真实业务推进拆成两条并行主线。

标准顺序固定为：

**任务意图 → review plan → 回写计划 → optimize subagent prompt → spawn → 结果回流**

其中：

1. **任务意图** 作为真实任务入口，先明确要做什么、为什么做、边界在哪里。
2. **review plan** 负责在执行前校验计划结构、任务边界与完成标准。
3. **回写计划** 用于把 review 后的结论落回主计划，保持计划与执行一致。
4. **optimize subagent prompt** 在派发前收敛约束、补齐上下文、降低偏题概率。
5. **spawn** 只在前述步骤完成后执行。
6. **结果回流** 负责把执行结果、偏差和新发现持续回写到流程与产品观察中。

### 主路与旁路

- **主路**：真实任务必须经过上述默认流程。
- **旁路**：仅保留极小任务、纯同步确认、紧急止血等少数例外。
- **非目标**：不再为单独的拟真实验开新主线，也不把工具验证当作独立目的。

### 观察与收敛方向

真实任务推进过程中要同时收敛：

- 网页端的可观测性。
- 真实业务接入边界。
- 计划评审质量。
- prompt 优化效果。
- 接口与产品面的摩擦点。

## Alternatives Considered

- 继续把拟真实验作为主线：被拒绝，因为无法稳定暴露真实项目中的接口摩擦与流程问题。
- 将 SkillForge 只当作可选工具层：被拒绝，因为无法形成统一的负责人默认工作流，也难以沉淀持续优化闭环。
- 只做工具验证，不纳入真实任务推进：被拒绝，因为验证结果与实际业务场景脱节，沉淀价值有限。

## Consequences

- 正向：真实任务不再与工具验证割裂，流程优化会直接来自业务推进中的问题。
- 正向：计划评审、prompt 优化与结果回流被统一到同一条默认链路里，减少分叉。
- 正向：网页端可观测性和接口收敛会随着真实任务推进同步演进。
- 取舍：例外边界仍依赖负责人判断，容易在急任务里被放大使用。
- 取舍：真实任务会更直接暴露流程缺口，因此短期内返工和调整会增加。
- 验证锚点：后续真实项目推进是否稳定遵循“任务意图 → review plan → 回写计划 → optimize subagent prompt → spawn → 结果回流”的主路。
