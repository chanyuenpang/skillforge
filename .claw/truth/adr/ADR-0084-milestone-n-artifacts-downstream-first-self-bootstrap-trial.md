# ADR: Milestone N 产物文件下沉与自举试跑作为稳定锚点

## Status

accepted

## Context

Milestone N 已形成一组稳定的治理产物，包括负责人裁决、12 条规则层以及 workflow 草案。此前这些内容主要停留在运行期记录或临时产物里，不便于后续复用、引用和检索，也不利于把这次试跑沉淀成可持续的仓库级锚点。

本次计划的目标是把这些已形成的稳定决策正式写入仓库文件，作为后续执行、复盘和扩展时可以直接引用的基线。

## Decision

Milestone N 的已稳定产物要下沉为仓库内的持久化 truth 资产，形成三个可复用锚点：

1. **负责人裁决**：作为阶段推进和边界判断的稳定依据。
2. **12 条规则层**：作为日常执行约束的长期规则集。
3. **workflow 草案**：作为流程顺序、分支和回流的执行参考。

这次“第一单自举试跑”不只是在记录一次任务结果，而是把上述产物正式落到仓库文件中，成为后续任务可引用的稳定输入。

## Alternatives Considered

- 只保留在运行期计划或会话记录中：被拒绝，因为无法稳定检索，也无法作为后续任务的基线。
- 仅写入临时说明文档：被拒绝，因为临时文档不适合作为长期治理锚点。
- 把规则、workflow 和裁决继续分散在多个任务记录里：被拒绝，因为会导致引用成本高、边界不清晰。

## Consequences

- 正向：负责人裁决、规则层与 workflow 草案变成可检索、可复用的仓库级资产。
- 正向：后续任务可以直接引用这些稳定锚点，减少重复解释和上下文丢失。
- 正向：自举试跑本身也成为可复盘的过程样本，便于验证“先沉淀再执行”的路径。
- 取舍：把运行期产物正式沉淀后，后续修改需要更谨慎，避免把临时试验写成长期规则。
- 风险：若后续没有同步更新锚点，仓库中的稳定文档可能与实际执行偏离。
- 验证锚点：后续所有引用 Milestone N 的任务，都应优先从仓库 truth 文档读取规则与决策，而不是回看会话临时记录。
