# ADR: SkillForge 第二阶段增强坚持验证优先，暂不进入深治理

## Status

accepted

## Context

第二阶段入口已经被明确收口：不是把第一阶段的可演示面继续横向扩张，而是先补齐阶段一增强项，把运行中心与知识资产从“可演示”提升到“可复现、可回归、可托底”。

计划记录明确给出一个稳定约束：第二阶段入口采用单选 A，先做运行中心非空样本验证、知识资产 `skill-fixture` 分支抽测，以及轻量回归基线与一致性回写；不混合推进，也不直接进入写操作、资产治理或更深编排能力建设。

这个决策需要沉淀，因为它会长期约束后续实现顺序：阶段推进先看验证密度与可信度，不把“更深能力”当成默认下一步。

## Decision

决定将 SkillForge 第二阶段增强固定为“验证优先、深治理后置”的推进策略：

1. 先补运行中心非空样本验证，确认最小可回滚的样本构造路径。  
2. 再补知识资产 `skill-fixture` 分支抽测，补齐已验证事实。  
3. 同步建立阶段一轻量回归基线，覆盖关键 happy path、零态与错误态。  
4. 只有在上述增强完成后，才回写阶段判断与下一阶段入口建议。  
5. 暂不进入写操作、资产治理或更深编排能力建设；第二阶段不采用混合推进。

这里的核心不是扩功能，而是先把验证密度、演示可信度和回归托底做稳，再决定是否进入更深水区。

## Alternatives Considered

- 直接进入写操作或资产治理：被拒绝，因为阶段一增强项尚未补齐，容易让稳定基线失真。
- 同时推进增强项与更深编排能力：被拒绝，因为会把验证任务和能力建设混在一起，难以形成清晰决策基线。
- 只做一次性演示而不补回归基线：被拒绝，因为无法把“可演示”提升为“可复现、可回归、可托底”。

## Consequences

- 正向：第二阶段的第一优先级变成验证密度与回归托底，而不是盲目扩能力。
- 正向：运行中心与知识资产的增强项可以形成可复用的阶段基线，后续判断更清晰。
- 正向：`skill-fixture` 分支抽测和轻量回归清单会成为后续变更的稳定锚点。
- 取舍：短期内不会直接进入写操作、资产治理或更深编排，能力扩张节奏会更慢。
- 风险：如果样本构造路径或回归基线定义过窄，后续扩展时仍需重新补边界。
