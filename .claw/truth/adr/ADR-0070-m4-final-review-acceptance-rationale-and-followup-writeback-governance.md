# ADR: M4 最终审查验收口径与跟随式文档回写治理

## Status

accepted

## Context

P7 的首条真实样本已经进入最终审查收口，但如果没有先把验收裁决对象、通过/不通过/需补证据口径、以及跟随式文档回写边界固定下来，后续审查和治理就容易回到“先做后说”的临时状态，导致裁决口径漂移、回写越界、阶段禁区失守。

M4 的作用不是继续扩实现，而是把最终审查所需的负责人级治理骨架压实，确保后续真正派发审查型任务时，有明确的裁决范围、证据标准和回写边界可依。

## Decision

决定将 M4 固化为“最终审查验收口径与跟随式文档回写治理骨架”，并按以下规则推进：

1. 先明确验收裁决对象，再谈审查执行；审查范围只覆盖首条真实样本的最终审查所需对象，不扩展到新功能实现。
2. 通过 / 不通过 / 需补证据 的口径要显式固定，作为后续审查结论和卡片字段的统一标准。
3. 跟随式文档回写必须设置可写 / 不可写边界，禁止把自动生成内容、实现存在感或越界承诺写成最终事实。
4. 审查类与治理类任务必须拆成原子任务，并提前写清依赖关系、并行窗口、卡片结构与阶段禁区。
5. 后续真正的审查执行型 subplan 必须以这套骨架为起点，而不是重新临时定义裁决口径。

## Alternatives Considered

- 直接把 M4 当成“已经完成正式审查”来收口：被放弃，因为这次完成的是执行骨架，不等于真实样本已经生成最终裁决卡。
- 不显式固定通过 / 不通过 / 需补证据 口径：被放弃，因为会让后续裁决依赖口头判断，缺乏可审计性。
- 不区分可写 / 不可写边界：被放弃，因为容易把临时内容、自动生成痕迹或越界承诺写入 truth。
- 不拆审查 / 治理原子任务：被放弃，因为会让后续派发再次混淆职责。

## Consequences

- 正向：后续审查任务有了稳定的裁决口径，减少反复改口和结论漂移。
- 正向：可写 / 不可写边界被显式固定后，truth 回写更可审计，也更不容易越界。
- 正向：审查与治理任务拆分后，派发更清晰，依赖关系更容易管理。
- 取舍：这次完成的是治理骨架收口，不等于真实样本已经完成正式审查并生成最终裁决卡。
- 风险：如果后续审查派发不沿用这套边界，M4 的收口价值会迅速衰减。
