# mc-task-tracking：任务跟踪与负载分析

## 结论

`mc-task-tracking` 适合沉淀为“查询、快照、报表、依赖链”一体化的任务观察层，长期目标不是单次列表，而是持续看清任务流动和阻塞关系。

## 长期行为 / 规则

- 支持按状态、Worker、时间、优先级、依赖等多个维度查询任务。
- 看板应能产出状态快照，便于对比当前盘面与历史变化。
- 周期报表应覆盖任务分布、Worker 负载与阻塞情况。
- 依赖链分析要能暴露阻塞关系，而不是只显示任务表面状态。

## 关联代码

| 路径 | 作用 |
| ---- | ---- |
| `SKILL.md` | 技能骨架入口，定义查询维度、快照、报表与依赖分析能力。 |

## 真实调用链路

1. 按查询条件拉取任务集合。
2. 聚合生成状态快照与周期报表。
3. 分析 Worker 负载和依赖链，定位阻塞点。

## 已知陷阱

- 只看状态列表会丢掉依赖关系和负载信息。
- 只做一次性查询而不提供快照/报表，难以支持趋势判断。
- 依赖链如果不显式展示，阻塞根因很容易被误判。

## 验证标准

- 能按多个维度稳定筛选任务。
- 能输出可比对的状态快照和周期报表。
- 依赖链与阻塞关系可被清楚识别。
