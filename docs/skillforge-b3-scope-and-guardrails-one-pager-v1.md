# SkillForge B3 范围与边界守门说明（Skeleton 库原型）

## A. 本页目的
本文只用于锁定 B3 的可交付边界与对外口径，不扩展到后续阶段能力承诺。

## B. B3 仅解决的问题
- Skeleton 作为结构化骨架资产的定位
- Skeleton 最小对象字段、状态与版本语义
- `Skeleton → StepPlan` 映射与 `skeletonRef` 追溯约束
- 原型层“创建 → 应用 → 追溯”最小可治理链路

## C. B3 明确不做
- 智能推荐
- 质量评分
- 自动优化 / 自动编排策略
- 复杂可视化编排器
- 批量应用 / 跨项目协同深治理
- 跨域深联动自动化
- 任何 B4+ 的策略化、规模化能力承诺

## D. 状态口径
### 已实现
代码 / 对象 / 路径 / 规则已存在。

### 已验证
有明确证据链的真实验证，不能用“代码存在”替代。

### 未验证
已设计或已实现但缺乏实测证据，必须显式标注。

### 红线
- 任何“闭环”都必须带限定词：定义闭环 / 空数据闭环 / 业务样本闭环。
- 任何“可用”都必须指明层级：对象层 / 门禁层 / 端到端。
- 禁止把“分支已实现、规则已写、文档已定稿”写成“happy path 全量验证完成”。

## E. 越界表述禁用词
- Skeleton 智能推荐已具备 / 即将具备
- Skeleton 质量评分已进入落地
- 可自动生成高质量 StepPlan，基本不需人工
- 编排策略优化能力已成型
- Skeleton 与执行复盘已自动闭环
- B3 已完成跨域深联动
- B3 已覆盖多项目协同治理
- 已实现 = 已验证
- 空数据 / 代码分支验证 = 业务样本全量验证

## F. 对外叙事模板
第一段：B3 当前只推进 Skeleton 库原型的最小可治理链路，重点在创建、应用、版本绑定与追溯引用，不外推为智能化或规模化治理能力完成。

第二段：评分、推荐、自动优化与跨域深联动仍属于后续阶段方向，是否进入交付范围以后续阶段退出条件为准。

## G. 发布前自检清单
- 是否把“定义/实现”误写成“验证完成”
- 是否出现 B4+ 能力前置承诺
- 是否所有“完成/可用/闭环”都带范围限定词
