# SkillForge 负责人裁决页（v2）

## ① 裁决目标与边界
本页用于在第二、第三、第四阶段均已收口后，形成统一的负责人裁决口径与下一轮主计划入口判断。

本页只作为负责人裁决输入与负责人级判断记录页：
- 不作为阶段自动切换结论页
- 不作为高阶能力成立证明页
- 不作为规模化成熟或默认深执行批准页

固定边界句：已具备负责人裁决所需的统一基础输入，但裁决位仍按负责人判断受控开启。

固定裁决原则：
- 阶段收口完成 ≠ 下一阶段自动进入
- 条件推进成立 ≠ 高阶能力已成立
- 已实现 ≠ 已验证 ≠ 可规模化运营
- 文档/规则层收口完成 ≠ 产品主线已真实落地
- 候选能力已定义 ≠ 候选能力已解锁

## ④ 负责人判断：下一轮主计划的目标切换
负责人判断如下：

前四阶段已经完成“收口、守门、补证优先级、候选能力治理、执行主线准备”的规则层工作；下一轮主计划不应继续以治理收口为主线，而应切换为：

> 把 SkillForge 从“规则/裁决/候选能力已定义”推进到“最小真实执行闭环 + 可验证产品主线”落地。

也就是说，下一轮主计划的核心目标不是继续扩写治理文档，而是把一条最小、真实、可操作、可追溯、可验证、可复盘、可回沉的产品主线真正做出来。

## ⑤ 下一阶段目标（负责人级定义）
### 总目标
建立 SkillForge 的最小真实执行闭环主线，使其从治理完备进入可被真实使用、真实回放、真实验证、真实复盘的产品状态。

### 目标拆解
#### 1. 真实可操作
- 用户可发起、编辑、提交、审批、执行一条最小任务链
- 不再停留在只读、候选、定义层

#### 2. 真实可追溯
- Task / PromptDraft / StepPlan / Approval / ExecutionRun / Retro / Asset Feedback 形成连续对象链
- 每一步都有身份、状态、版本与引用关系

#### 3. 真实可验证
- 不以“代码已存在”或“空数据闭环”代替验证
- 至少形成一条真实样本、真实回归、真实验收链

#### 4. 真实可复盘与回沉
- 执行后可回看
- 回看后可形成结构化复盘
- 复盘结果可回沉到编排资产或知识资产

## ⑥ 完整落地形态（负责人验收图）
当下一轮主计划完成时，SkillForge 的最小完整落地形态应满足：

### A. 用户侧闭环
用户可以完成：
- 创建或选择一个真实任务
- 基于 `PromptDraft` / `StepPlan` / `Skeleton` 组织执行方案
- 提交到审批链
- 审批通过后进入执行
- 在执行过程中查看状态、结果、证据
- 在执行后查看复盘记录
- 将复盘结果关联回编排资产或知识资产

### B. 系统侧闭环
系统内部至少形成连续链：
- `Task / Request`
- `PromptDraft`
- `StepPlan`
- `Approval / Risk Gate`
- `ExecutionRun`
- `Evidence / Transcript / Log`
- `Retro`
- `Asset Writeback / Skeleton Feedback`

要求：
- 每个节点有身份
- 每个节点有状态
- 每个节点有证据锚点
- 相邻节点之间可追溯、可回看、可校验

### C. 产品侧闭环
- 运行中心不再只是只读看板，而是最小可操作工作台
- 审批中心不再只有治理规则，而是有真实门禁链
- 编排资产层不再只是文档对象，而是可被真实调用与回看
- 复盘沉淀层不再只是描述概念，而是有可用的结构化反馈入口
- truth / phase / spec / ADR 继续做回写层，但不再代替真实产品主线本身

## ⑦ 未验证池与风险保留（统一版）
### A. 自动化能力（继续冻结）
- 自动回写
- 自动优化
- 自动根因诊断
- 自动修复 / 自动回滚
- 自动一致性修复
- 自动推荐联动

### B. 规模化与跨项目治理（继续冻结）
- 大规模真实业务样本充分性
- 复杂血缘图谱
- 深度影响分析
- 跨项目规模化知识回流
- 复杂联动看板

### C. 稳定性与异常处理（继续保留）
- 复杂异常场景
- 长期稳定性
- 恢复能力充分验证不足
- 回归失败后的系统性回退演练不足

### D. 表述与外推风险
- 把“统一输入成立”误写成“新阶段自动成立”
- 把“执行主线准备完成”误写成“执行主线已落地”
- 把“候选能力已定义”误写成“候选能力已解锁”
- 把“最小样本验证”外推成“全量可运营”
- 把“文档完备”误写成“产品闭环已完成”
