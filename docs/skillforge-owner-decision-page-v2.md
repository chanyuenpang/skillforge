# SkillForge 负责人裁决页（v2）

## ① 裁决目标与边界
本页用于在第二、第三、第四阶段均已收口后，形成统一的负责人裁决口径与下一轮主计划入口判断。

本页只作为负责人裁决输入与负责人级判断记录页：
- 不作为阶段自动切换结论页
- 不作为高阶能力成立证明页
- 不作为规模化成熟或默认深执行批准页

固定边界句：已具备负责人裁决所需的统一基础输入，但裁决位仍按负责人判断受控开启。

固定裁决原则：
- 阶段收口完成 ≠ 下一阶段自动进入
- 条件推进成立 ≠ 高阶能力已成立
- 已实现 ≠ 已验证 ≠ 可规模化运营
- 文档/规则层收口完成 ≠ 产品主线已真实落地
- 候选能力已定义 ≠ 候选能力已解锁

## ③ 当前可签收结论（统一裁决基线）
以下内容可由负责人签收为“统一裁决输入基线成立”：
- 第二、第三、第四阶段的治理、事实、证据与边界收口材料均已成文并可追溯
- 阶段推进口径已统一为“按条件治理”，并已显式禁止自动切换叙事
- 未验证池、候选能力、补证链路、回退条件与执行主线准备基线已具备统一入口
- 继续推进下一轮主计划所需的最低负责人依据集已经具备

以下内容不可在本页签收为既成事实：
- 第二/第三/第四阶段自动推导出更高阶段默认进入
- 自动化能力已落地
- 规模化治理已成熟
- 全链路 / 全量 / 长周期稳定性验证已完成
- 真实产品主线已经闭环落地

## ④ 负责人判断：下一轮主计划的目标切换
负责人判断如下：

前四阶段已经完成“收口、守门、补证优先级、候选能力治理、执行主线准备”的规则层工作；下一轮主计划不应继续以治理收口为主线，而应切换为：

> 把 SkillForge 从“规则/裁决/候选能力已定义”推进到“最小真实执行闭环 + 可验证产品主线”落地。

也就是说，下一轮主计划的核心目标不是继续扩写治理文档，而是把一条最小、真实、可操作、可追溯、可验证、可复盘、可回沉的产品主线真正做出来。

## ⑤ 下一阶段目标（负责人级定义）
### 总目标
建立 SkillForge 的最小真实执行闭环主线，使其从治理完备进入可被真实使用、真实回放、真实验证、真实复盘的产品状态。

### 目标拆解
#### 1. 真实可操作
- 用户可发起、编辑、提交、审批、执行一条最小任务链
- 不再停留在只读、候选、定义层

#### 2. 真实可追溯
- Task / PromptDraft / StepPlan / Approval / ExecutionRun / Retro / Asset Feedback 形成连续对象链
- 每一步都有身份、状态、版本与引用关系

#### 3. 真实可验证
- 不以“代码已存在”或“空数据闭环”代替验证
- 至少形成一条真实样本、真实回归、真实验收链

#### 4. 真实可复盘与回沉
- 执行后可回看
- 回看后可形成结构化复盘
- 复盘结果可回沉到编排资产或知识资产

## ⑥ 完整落地形态（负责人验收图）
当下一轮主计划完成时，SkillForge 的最小完整落地形态应满足：

### A. 用户侧闭环
用户可以完成：
- 创建或选择一个真实任务
- 基于 `PromptDraft` / `StepPlan` / `Skeleton` 组织执行方案
- 提交到审批链
- 审批通过后进入执行
- 在执行过程中查看状态、结果、证据
- 在执行后查看复盘记录
- 将复盘结果关联回编排资产或知识资产

### B. 系统侧闭环
系统内部至少形成连续链：
- `Task / Request`
- `PromptDraft`
- `StepPlan`
- `Approval / Risk Gate`
- `ExecutionRun`
- `Evidence / Transcript / Log`
- `Retro`
- `Asset Writeback / Skeleton Feedback`

要求：
- 每个节点有身份
- 每个节点有状态
- 每个节点有证据锚点
- 相邻节点之间可追溯、可回看、可校验

### C. 产品侧闭环
- 运行中心不再只是只读看板，而是最小可操作工作台
- 审批中心不再只有治理规则，而是有真实门禁链
- 编排资产层不再只是文档对象，而是可被真实调用与回看
- 复盘沉淀层不再只是描述概念，而是有可用的结构化反馈入口
- truth / phase / spec / ADR 继续做回写层，但不再代替真实产品主线本身

## ⑦ 未验证池与风险保留（统一版）
### A. 自动化能力（继续冻结）
- 自动回写
- 自动优化
- 自动根因诊断
- 自动修复 / 自动回滚
- 自动一致性修复
- 自动推荐联动

### B. 规模化与跨项目治理（继续冻结）
- 大规模真实业务样本充分性
- 复杂血缘图谱
- 深度影响分析
- 跨项目规模化知识回流
- 复杂联动看板

### C. 稳定性与异常处理（继续保留）
- 复杂异常场景
- 长期稳定性
- 恢复能力充分验证不足
- 回归失败后的系统性回退演练不足

### D. 表述与外推风险
- 把“统一输入成立”误写成“新阶段自动成立”
- 把“执行主线准备完成”误写成“执行主线已落地”
- 把“候选能力已定义”误写成“候选能力已解锁”
- 把“最小样本验证”外推成“全量可运营”
- 把“文档完备”误写成“产品闭环已完成”

## ⑧ 裁决口径（负责人签署区）
### 主裁决句
同意继续推进下一轮主计划，但本次仅确认“统一裁决输入基线成立”，并明确下一轮应转入“最小真实执行闭环与产品主线落地”，不构成阶段自动切换或高阶能力已成立。

### 补充裁决句
继续推进 = 从治理收口转入最小真实产品闭环建设；不等于自动批准高阶能力放开。

### 风险保留句
所有未验证池能力继续冻结；只有在真实补证、真实回归与边界复核通过后，才可进入对应候选能力的受控推进。

## ⑨ 附加条件与闸门
- 基线回归先行
- 真实样本先行，不得再用空数据闭环替代产品验收
- 先打通一条最小真实执行主线，再讨论高阶能力扩展
- 冲突、证据不足、回归失败时必须回退到候选 / 条件化状态
- 每条新结论必须同时写明：证据锚点、覆盖范围、未覆盖范围
- 文档回写必须跟随真实能力落地，不得继续让文档长期跑在产品前面

## ⑩ 裁决输出项（本页最终沉淀）
- 裁决结论：同意继续推进下一轮主计划
- 裁决性质：确认统一裁决输入基线成立
- 下一轮主线：最小真实执行闭环与产品主线落地
- 不构成：阶段自动切换 / 高阶能力成立 / 默认深执行批准 / 规模化成熟判定
- 附加条件：基线回归先行、真实样本先行、冲突即回退
- 下次复核触发条件：关键主线跑通、证据补齐、边界变化、回归结果异常、候选能力拟解锁

## ⑪ 下一轮主计划承接说明
本页之后的正确承接动作，不是继续停留在治理补丁，而是：
1. 以本页作为统一负责人裁决输入基线；
2. 新开下一轮主计划，主题锁定为“最小真实执行闭环与产品主线落地”；
3. 先定义最小真实对象链、最小执行链、最小证据链与最小复盘回沉链；
4. 再据此拆出实现、验证、回写三类原子任务；
5. 文档只做跟随式回写，不再代替主线本身。
