# SkillForge 产品 100% 终态定义（v1）

> 本文仅做终态定义，不做里程碑规划。作为主计划 Task 1 的产出，供后续差距分析与里程碑编排作为评价基线。

---

## 功能面

SkillForge 是一条完整的"意图 → 规范 → 执行 → 回流"链路。100% 时，负责人输入任务意图后，SkillForge 自主完成 review plan、回写、optimize prompt、spawn 派发、结果收口，每步都有规则层（12 条）与工作流层（主路径/例外/重试）的门禁保障。planning + spawn skill 的 SKILL.md 已完全落地，分支任务自动拆解派发，回流后自动完成达成度判定与偏差闭环，可回沉结论同步到 Skeleton 资产。

## 观测面

网页端 100% 时，负责人在浏览器中完成"看全局 → 查待办 → 审详情 → 做决策"的全部操作。总览工作台聚合运行中任务、待审批队列、异常与资产趋势。运行中心具备 PromptDraft/StepPlan 可视化编辑、Run 时间线回看、证据锚点展开、SkillForge 观察区（review/optimize 输入输出与脱敏日志）。审批队列支持逐条审查决策，跨域引用链可点击追溯。知识资产层可检索浏览 Skeleton 库与模板片段，追踪引用次数与效果反馈。

## 稳定性面

服务托管 100% 时，所有持续服务（web-server、SkillForge 执行器、状态调度）以 systemd user service 为唯一托管层，不存在"启动后被杀"的窗口。Ubuntu 服务器上所有 AI 工作流统一收敛于此，故障恢复策略已在执行工作流中定义并验证。服务状态通过 systemctl 与网页健康检查双通道实时确认，异常 30 秒内上报飞书通知。

## 流程面

流程面 100% 时，日常推进形如：早上看一眼总览面板确认所有任务正常，发起新任务给出意图。SkillForge 自动 review plan 审阅可执行性、回写结论、optimize prompt，完成后 spawn 或收口。每步同步到 web 端，负责人随时浏览进展。中午回来，SkillForge 已完成 spawn 并回流结果，负责人审阅达成度与偏差，标记收口或修改后重发。整个过程不再手动写 plan、拆子任务、整理证据——SkillForge 接管"规范→执行→回流→决策"循环，负责人只做判定与修正。
