# SkillForge B1 审批与执行衔接断点清单（v1）

## 1. 提交 → 审批 断点
### GAP-S2A-01 提交包边界不够显式
- 现象：用户侧可能缺少“提交的是哪一版、哪些字段被锁定”的强提示。
- 影响对象：PromptDraft / StepPlan / Approval
- 证据级别：未验证
- 是否可 B1 最小补位：是

### GAP-S2A-02 提交前检查结果与审批受理衔接偏弱
- 现象：检查清单虽已定义，但进入审批单后的检查摘要挂载位不明确。
- 影响对象：PromptDraft / StepPlan / Approval
- 证据级别：未验证
- 是否可 B1 最小补位：是

### GAP-S2A-03 状态切换确认节点不够可感知
- 现象：`ReadyForPlan / ReadyForApproval → LockedForApproval` 之间可能缺少显式确认锁定节点。
- 影响对象：PromptDraft / StepPlan / Approval
- 证据级别：未验证
- 是否可 B1 最小补位：是

## 2. 审批 → 执行 断点
### GAP-A2E-01 获准版本绑定不够显式
- 现象：执行前缺少“审批通过的是哪一版 StepPlan / PromptDraft”的确认锚点。
- 影响对象：Approval / Run / StepPlan
- 证据级别：未验证
- 是否可 B1 最小补位：是

### GAP-A2E-02 审批结论到执行动作语义映射不足
- 现象：通过 / 驳回 / 补充后重提在执行入口处的行为差异提示可能不足。
- 影响对象：Approval / Run
- 证据级别：未验证
- 是否可 B1 最小补位：部分可补

### GAP-A2E-03 审批完成后的回流入口可能断层
- 现象：若缺统一回跳与定位，审批完成后回到哪条 run / 哪个任务详情不够连贯。
- 影响对象：Approval / Run
- 证据级别：未验证
- 是否可 B1 最小补位：是

## 3. 执行 → 回看 断点
### GAP-E2R-01 执行事实与审批证据映射不够直观
- 现象：运行详情虽可见日志/审批入口，但“本次执行对应哪次审批决策”未必一跳可见。
- 影响对象：Run / Approval
- 证据级别：未验证
- 是否可 B1 最小补位：是

### GAP-E2R-02 执行记录与计划版本追溯链可见性不足
- 现象：若页面未并列展示 PromptDraft / StepPlan / Approval / Run 的版本与状态，复盘成本高。
- 影响对象：Run / StepPlan / PromptDraft
- 证据级别：未验证
- 是否可 B1 最小补位：是

### GAP-E2R-03 异常 / 失败态回看口径可能不统一
- 现象：若缺统一证据槽位（日志、检查点、审批意见回链），容易形成“有记录但不可解释”。
- 影响对象：Run / Approval
- 证据级别：未验证
- 是否可 B1 最小补位：部分可补

## 4. B1 可最小补位的断点
- 提交时补版本与锁定范围的显式展示
- 提交前检查结果补最小证据挂载位
- 审批通过后补“获准版本”标识与执行入口同屏可见
- 运行详情补四段链路最小追溯卡片
- 审批回流补稳定回跳点

## 5. 暂不在 B1 解决的断点
- 审批策略引擎细则与复杂自动判定
- 自动化版本差异分析与自动冲突修复
- 深度可视化编排器级别的体验
- 执行结果自动反哺 Prompt / StepPlan 的智能闭环
- 跨任务、跨域推荐式衔接与规模化治理看板

## 6. 结论
B1 当前最关键的不是扩动作数量，而是把提交、审批、执行、回看四段主链之间的最小断点补齐。优先补位应聚焦版本显式性、检查摘要挂载、执行入口绑定与运行详情中的最小追溯卡片。
