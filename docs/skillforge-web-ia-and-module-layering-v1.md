# SkillForge 网页产品信息架构与模块分层设计（v1）

## 1. 设计目标与范围

本设计文档聚焦 SkillForge 网页端的**信息架构（IA）与模块分层**，目标是把当前“风险审批子域可用”的状态，升级为“产品壳层成立、模块边界清晰、可持续扩展”的网页产品形态。

本阶段设计目标：

1. 建立统一产品入口与一级导航，避免网页端被等同为单一 `/risk/*` 页面集合。
2. 明确模块分层关系，形成“壳层承载、子域入驻、能力渐进补齐”的结构。
3. 对齐当前真实实现与已存在能力（风险审批、总览工作台、占位模块、现有 API），不虚构已落地深功能。
4. 提供对象到页面/接口的映射与关键用户流，支撑后续研发排期和评审。

范围边界：

- **包含**：网页 IA、导航结构、页面地图、模块分层、对象映射、关键流转。
- **不包含**：视觉风格细化、逐页面组件规范、品牌重设计、未实现后端能力承诺。

## 2. 当前网页产品现状

当前 SkillForge 网页端已经从“审批能力相对可用”进一步推进到“**审批闭环稳定、运行中心与知识资产第一刀已成立**”阶段。

1. **已相对成型**：风险审批链路（任务执行前置审批、结果确认、可追溯记录）继续保持可用，是当前产品可信主干。  
2. **产品壳层已成立**：总览工作台与统一壳层已经形成，顶层导航下现已共存总览、风险审批、运行中心、知识资产、设置五个入口。  
3. **运行中心第一刀已落位**：  
   - 路由：`/run-center`、`/run-center/runs`、`/run-center/runs/:runId`  
   - API：`/api/run-center/*` 已接入  
   - 当前已验证的是“空数据闭环成立”；有数据 happy path 尚未全量验证。  
   - 相关对象定义与状态流转见 `docs/skillforge-run-center-domain-spec-v0.1.md`。  
4. **知识与资产第一刀已落位**：  
   - 路由：`/knowledge-assets`、`/knowledge-assets/:assetId`  
   - API：`/api/knowledge-assets*` 已接入  
   - 白名单来源为 `docs/` + `fixtures/`  
   - doc 详情 happy path 已实测；skill-fixture 详情分支代码已实现，但尚未单独补第二条命令样例抽测，不记为已验证完成。  
   - Skeleton 对象定义与应用语义见 `docs/skillforge-knowledge-asset-domain-spec-v0.1.md`。  
5. **现有 API 能力分布仍不均衡**：风险审批、运行中心、知识资产都已有最小产品化消费；更深层的编排、治理与跨域对象 API 尚未在网页端全面展开。

当前阶段判断：  
**阶段一已形成可演示产品面，但运行中心与知识资产仍属于“第一刀已成立、增强项待补齐”的状态。**

## 3. 一级导航与页面地图

### 3.1 一级导航（L1）

当前一级导航已经在同一壳层下实现并共存：

1. **总览工作台**（默认入口）
2. **运行中心**（当前已落地第一刀）
3. **知识与资产**（当前已落地第一刀）
4. **审批与风控**（当前较成熟）
5. **设置**

其中，审批与风控仍是当前较成熟子域；运行中心与知识与资产已完成第一刀接入，但更深层能力仍处于建设中。
### 3.2 页面地图（当前 + 近期目标）

- `/` 或工作台入口  
  - 总览工作台（已落位 / 在用）
- 运行中心  
  - 任务台（任务列表、状态、审批态）  
  - 任务编排（Prompt 草案、步骤拆解、执行参数）【建设中】  
  - 执行记录（运行日志、阶段产物、审批轨迹）
- 知识与资产  
  - Skeleton 库（按任务类型 / 团队沉淀结构化计划骨架）【建设中】  
  - 模板与片段（Prompt 模板、步骤片段、参数模板）【建设中】  
  - 复用记录（被哪些任务调用、效果反馈）【建设中】
- 审批与风控  
  - 待审批  
  - 审批历史  
  - 策略与阈值（基础配置）
- 设置  
  - 项目配置  
  - 成员与权限  
  - 接口与集成（预留）

页面地图原则：
- 运行中心负责**一次任务的发起、编排、执行、回看**；
- 知识与资产负责**跨任务可复用结构（skeleton / 模板）沉淀**；
- 审批与风控负责**关键节点放行与追责闭环**。

## 4. 模块分层

为避免能力悬空，本阶段按“展示层—编排层—执行与审批层—资产层”定义模块分层。

### 4.1 L1 展示与交互层（Web IA）

职责：

- 提供总览工作台、运行中心、知识与资产、审批与风控、设置五个一级入口
- 建立用户可见的导航关系、页面框架与状态提示
- 先把两类长期场景形成稳定可操作入口，而不追求复杂可视化

### 4.2 L2 任务编排层（建设中）

职责：

- 承接 subagent prompt 优化：把用户意图转为可执行 prompt 草案
- 承接步骤化编排：支持步骤拆解、顺序调整、输入输出约束
- 满足“可编辑、可提交、可追溯”的最小要求

当前状态：

- 初版更偏表单化 / 列表化的浅实现，尚未达到强可视化编排器形态。

### 4.3 L3 执行与审批层（相对成熟）

职责：

- 承接任务执行状态流转、风险节点拦截、人工审批放行
- 记录审批原因与执行结果关联，形成最低治理闭环

当前状态：

- 风险审批主链相对成熟，可作为当前产品可信主干。

### 4.4 L4 知识资产层（建设中）

职责：

- 承接 workflow skeleton：结构化计划骨架（目标、阶段、检查点、产物定义）
- 承接模板资产：prompt 模板、步骤片段、参数建议
- 与执行记录关联，形成“可复用但可裁剪”的资产沉淀

当前状态：

- 以库 / 模板 / 复用记录为初始承接位，后续再增强版本化、检索与效果反馈。

### 4.5 模块归属结论

- 场景 1（prompt 优化 / 步骤编排）主归属 **运行中心 + L2**，审批节点落到 **L3**。
- 场景 2（workflow skeleton）主归属 **知识与资产 + L4**，调用发生在 **运行中心** 发起阶段。
- 设置模块继续承接系统级配置、权限与集成入口，不与上述能力域抢职责。

## 5. 对象到页面/接口的映射关系

以下映射强调“当前可用 + 近期可接入”，不把未实现能力视作完成。

| 业务对象 | 主页面归属 | 次级页面 / 入口 | 建议接口（示意） | 当前状态 |
| --- | --- | --- | --- | --- |
| Task（任务实例） | 运行中心 / 任务台 | 执行记录 | `GET /tasks` `GET /tasks/{id}` | 基础可用 |
| PromptDraft（prompt 草案） | 运行中心 / 任务编排 | 任务详情侧栏 | `GET/PUT /tasks/{id}/prompt-draft` | 定义已建立，产品化建设中（见 `docs/skillforge-run-center-domain-spec-v0.1.md`） |
| StepPlan（步骤计划） | 运行中心 / 任务编排 | 执行前确认页 | `GET/PUT /tasks/{id}/step-plan` | 定义已建立，产品化建设中（见 `docs/skillforge-run-center-domain-spec-v0.1.md`） |
| Skeleton（结构化骨架） | 知识与资产 / Skeleton 库 | 运行中心创建任务时选择 | `GET /skeletons` `POST /skeletons` | 定义已建立，产品化建设中（见 `docs/skillforge-knowledge-asset-domain-spec-v0.1.md`） |
| TemplateSnippet（模板片段） | 知识与资产 / 模板与片段 | 任务编排插入 | `GET /snippets` | 建设中 |
| ApprovalRequest（审批请求） | 审批与风控 / 待审批 | 运行中心任务详情 | `POST /approvals` `GET /approvals/{id}` | 相对成熟 |
| ApprovalDecision（审批决策） | 审批与风控 / 审批历史 | 执行记录关联 | `POST /approvals/{id}/decision` | 相对成熟 |
| ExecutionRun（执行批次） | 运行中心 / 执行记录 | 审批历史回链 | `GET /runs/{id}` | 基础可用 |

映射原则：
- 所有“编辑类对象”（PromptDraft、StepPlan）必须在运行中心可见可改。
- 所有“复用类对象”（Skeleton、TemplateSnippet）必须在知识与资产可沉淀可检索。
- 所有“风险类对象”（ApprovalRequest / ApprovalDecision）必须在审批与风控统一查看。

## 6. 关键用户流

### 6.1 用户流 A：subagent 任务 prompt 优化 / 步骤化编排

1. 进入 **运行中心 - 任务台** 创建或选择任务。  
2. 在 **任务编排** 填写 / 生成 PromptDraft，并拆解 StepPlan（初版为结构化表单）。  
3. 提交执行前检查；若触发风险规则，进入 **审批与风控 - 待审批**。  
4. 审批通过后执行，结果回写 **运行中心 - 执行记录**。  
5. 用户在任务详情中复盘本次 prompt 与步骤效果，为后续模板化提供依据。

### 6.2 用户流 B：workflow skeleton 辅助结构化计划制定

1. 在 **知识与资产 - Skeleton 库** 新建或选择 skeleton（目标 / 阶段 / 检查点）。  
2. 在创建任务时将 skeleton 应用到任务，自动生成初版 StepPlan。  
3. 回到 **运行中心 - 任务编排** 做任务级微调（删减 / 重排 / 补充步骤）。  
4. 执行与审批按既有链路流转。  
5. 任务完成后，将有效结构回沉到 skeleton 或片段（当前可先人工确认后沉淀）。

### 6.3 风险审批主流（已成立）

总览工作台（待办聚合）  
→ 进入审批与风控列表  
→ 查看详情与证据  
→ 执行审查 / 审批动作  
→ 返回总览查看状态回流

## 7. 当前阶段边界与后续扩展点

### 当前边界（必须如实）

1. 风险审批链路相对完整，可作为当前产品可信主干。  
2. 运行中心第一刀已成立，但当前主要验证到空数据闭环；不宣称“有数据 happy path 全量验证完成”。  
3. 知识资产第一刀已成立，真实白名单来源为 `docs/` + `fixtures/`；doc 详情 happy path 已实测，skill-fixture 详情分支仍待单独抽测补齐。  
4. prompt 优化、步骤编排、skeleton 资产化仍为浅层实现：更偏“结构化输入 + 人工校正”，尚未达到“可视化强编排 + 自动优化闭环”。  
5. 总览与一级导航已提供可演示产品壳层，但多模块深功能仍在建设中。

### 后续扩展点（与 IA 一致，不超前承诺）

1. 运行中心：补齐有数据样本下的 happy path 验证、详情联调与更完整的异常态证据。  
2. 知识与资产：补齐 skill-fixture 详情分支的独立抽测，并逐步增强筛选、排序与更清晰的内容阅读体验。  
3. 审批与风控：将审批策略与任务类型 / skeleton 风险等级联动。  
4. 端到端闭环：执行结果自动反哺模板与 skeleton 推荐，但保留人工确认门槛。  
5. 对象追溯：强化 Task / PromptDraft / StepPlan / Skeleton / Approval / Run 跨页链路可解释性，引用链遵循 `PromptDraft → StepPlan → Approval → Run → Registry`（详见 `docs/skillforge-registry-minimal-reference-rules-v0.1.md`）。

---

## 8. 非目标

1. 不在本阶段进行逐页面视觉细节设计展开。
2. 不重构风险审批既有业务逻辑作为本设计前置条件。
3. 不将未接入 API 的功能写成“已可用”。
4. 不一次性承诺全模块深功能落地。
5. 不偏离现有壳层与总览工作台推进方向。
6. 不把“空数据闭环成立”混写为“业务数据链路已被完整验证”。
7. 不把“代码分支已实现”混写为“该分支 happy path 已实测通过”。
