# SkillForge P0：第五阶段验收图与主线定锚（v1）

## 1. 背景与边界
本文承接 `docs/skillforge-owner-decision-page-v2.md` 的统一负责人裁决口径，用于把第五阶段的完成态压缩成唯一主线：

> 把 SkillForge 从“规则/裁决/候选能力已定义”推进到“最小真实执行闭环与可验证产品主线”落地。

本文只定义第五阶段的负责人验收图与主线锚点：
- 不作为阶段自动切换结论页
- 不作为高阶自动化或规模化能力成立页
- 不以文档完备、代码存在或空数据闭环替代真实产品验收

固定边界：
- 已实现 ≠ 已验证 ≠ 可规模化运营
- 条件推进 ≠ 高阶能力已解锁
- 文档回写必须跟随真实能力落地，不得再由文档替代主线验收

## 2. 第五阶段三层闭环完成态

### 2.1 用户侧闭环（可真实使用）
第五阶段的最小完成态，是让用户能在同一主线里完成以下动作并留痕：
1. 创建或选择一个真实任务（非占位）
2. 编辑 `PromptDraft`，补齐目标、约束、验收标准
3. 形成 `StepPlan`，步骤具备 `input -> intent -> output -> check`
4. 提交审批并经过真实门禁
5. 审批通过后进入执行
6. 执行中可查看状态、结果、证据
7. 执行后可查看复盘，并把复盘结论关联到 Skeleton 或知识资产

判定要点：
- 至少 1 条真实任务链路跑通
- 审批前后状态变化清晰
- 用户可回看该链路历史

## 2.2 系统侧闭环（可追溯可校验）
系统内部应至少形成连续对象链：

`Task/Request -> PromptDraft@v -> StepPlan@v -> Approval/Risk Gate -> ExecutionRun -> Evidence/Transcript/Log -> Retro -> Skeleton修订决策/资产回沉入口`

每个节点的最低要求：
- 有唯一标识（ID / Ref）
- 有状态
- 有版本引用（至少 PromptDraft / StepPlan / Skeleton）
- 有证据锚点（谁、何时、做了什么）

关键约束：
- 未审批通过不得进入 Run
- Run 绑定获准版本
- Retro 必带覆盖范围 / 未覆盖范围
- Skeleton 只允许以新版本回沉，不覆盖旧版本

## 2.3 产品侧闭环（最小可运营主线）
第五阶段不追求大而全产品面，完成态是：
- 运行中心：从只读看板升级为“可编辑 + 可提交 + 可回看”的最小工作台
- 审批中心：不只提供规则文本，必须承载真实门禁决策
- 知识资产层（Skeleton）：至少可被一次真实任务应用，并可追溯到执行与复盘
- 文档层（truth / phase / spec / ADR）：只做跟随式回写，不抢主线定义权

验收判断：
- 有一条产品内可操作的真实端到端路径
- 有一条资产被应用并反馈的真实路径
- 有一次结果驱动文档回写的闭环样例

## 3. 本阶段必须落地项

### 3.1 单条真实任务样本贯通
- 要求：从 Task 到 Retro 全链路至少跑通一次
- 禁止：用空数据、伪造展示数据或仅代码存在代替

### 3.2 PromptDraft 与 StepPlan 的可编辑、可提交、可追溯
- 要求：满足运行中心子域规范中的最小字段与状态流转
- 重点：PromptDraft / StepPlan / Approval / Run 关系必须真实成立

### 3.3 审批门禁真实生效
- 要求：形成“未批不跑、批后可跑”的可审计证据
- 重点：审批不再只是规则文本，而是执行前硬门禁

### 3.4 ExecutionRun 证据化落地
- 要求：至少包含执行记录、结果、关联版本引用
- 重点：能支撑回看与后续 retro

### 3.5 Retro 结构化回沉入口可用
- 要求：至少能形成 `可回沉 / 暂不回沉 / 需补证据` 三类结论之一
- 重点：retro 必带证据锚点、覆盖范围、未覆盖范围

### 3.6 Skeleton 应用追溯最小闭环
- 要求：StepPlan 保留 `skeletonRef(id + version)` 并可回看
- 重点：至少有一次真实任务应用了 Skeleton，并能追溯到执行与复盘

### 3.7 跟随式文档回写样例成立
- 要求：至少完成一轮由真实主线结果驱动的 truth / phase / spec / ADR 最小回写
- 重点：文档跟随产品，不得反向代替产品验收

## 4. 继续冻结项（禁承诺表）
以下内容在第五阶段继续冻结，不得写成默认后续能力或既成事实：
- 自动回写（含 Skeleton 自动回写）
- 自动优化 / 自动步骤重排
- 自动根因诊断
- 自动修复 / 自动回滚 / 自动一致性修复
- 自动推荐联动（含高阶 Skeleton 推荐）
- 复杂血缘图谱 / 深度影响分析
- 跨项目规模化知识回流 / 复杂联动看板
- 长周期稳定性“已成熟”叙事

允许口径：
- 条件评估中
- 候选能力
- 需补证
- 未验证

## 5. 验收证据模板
第五阶段的每条负责人结论，至少附：
- 证据锚点
- 覆盖范围
- 未覆盖范围

模板：
- 结论：
- 证据锚点：
- 覆盖范围：
- 未覆盖范围：
- 回退条件：

## 6. 与后续 P1-P5 的接口约束
本页作为第五阶段 P1-P5 的唯一上位锚点：
- P1 只负责把最小真实对象链与状态机做实
- P2 只负责把最小真实执行主线的产品面做实
- P3 只负责把真实证据链与回归验收基线做实
- P4 只负责把 retro 与回沉入口做实
- P5 只负责把跟随式回写规则与触发边界做实

任何任务不得越界提前承诺：
- 自动化闭环已成立
- 规模化治理已成熟
- 全量 / 长周期稳定性已完成验证
