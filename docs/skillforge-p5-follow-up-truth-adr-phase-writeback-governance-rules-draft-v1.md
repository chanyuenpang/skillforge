# SkillForge P5：跟随式 truth / ADR / phase 回写治理规则草案（v1）

## 1. 背景与定位
本文承接：
- `docs/skillforge-p0-phase5-acceptance-map-and-mainline-anchor-v1.md`
- `docs/skillforge-p3-minimal-real-evidence-chain-and-regression-acceptance-baseline-draft-v1.md`
- `docs/skillforge-p4-retro-to-skeleton-minimal-writeback-loop-draft-v1.md`
- `docs/skillforge-owner-decision-page-v2.md`

用于把第五阶段的跟随式文档回写规则固定下来，明确：
- truth / ADR / phase 文档何时可写
- 什么属于可写事实
- 什么属于禁写承诺
- 什么必须继续挂账
- 何时必须回退口径

本文只定义第五阶段的“跟随式回写治理”规则：
- 不把文档写作当成完成态本身
- 不让文档先行替代真实产品与证据闭环
- 不允许把冻结能力、候选能力或局部样本外推为既成事实

## 2. 回写总原则
- 文档回写必须结果驱动、跟随主线
- 回写必须绑定真实对象链与真实证据
- 没有证据锚点的内容，不得写成“已成立”
- 每条回写结论必须附覆盖范围 / 未覆盖范围 / 回退条件
- 文档只能跟随真实闭环更新，不能反向定义完成态

## 3. 最小回写触发条件

### 3.1 truth 回写触发
允许触发的最小条件：
- 出现新的真实链路状态变化，并有证据锚点
- 某能力状态从 `未实现 -> 已实现` 或 `已实现 -> 已验证` 发生等级变化
- 冻结 / 候选 / 挂账状态发生变化，且未越过禁区

不允许触发：
- 仅有文档定义
- 仅有代码提交
- 空数据闭环
- 口头判断

### 3.2 ADR 回写触发
允许触发的最小条件：
- 跨域对象引用规则变化
- 审批门禁、版本固化、回沉决策链等关键机制发生取舍调整
- 人工规则升级到半自动 / 数据驱动，导致治理边界变化

不允许触发：
- 纯措辞润色
- 无语义变化的小修

### 3.3 phase 回写触发
允许触发的最小条件：
- 阶段内真实样本验收结果落地（通过 / 不通过）
- 出现偏差、回退、风险暴露并影响主线节奏
- roadmap 的阶段目标或边界口径发生调整

不允许触发：
- 无新增证据的重复总结

## 4. 可写 / 禁写 / 挂账规则

### 4.1 可写事实
允许写入的内容：
- 已发生且可追溯的事实（有 ID / Ref / 状态 / 版本 / 证据锚点）
- 已通过的最小验收项
- 明确附带覆盖范围与未覆盖范围的结论
- 人工治理结论（如 Retro 三分结论、人工评审结果、是否形成 Skeleton 新版本）

### 4.2 禁写承诺
不得写入的内容：
- 把候选能力写成既成事实
- 把自动回写 / 自动优化 / 自动诊断 / 自动修复 / 自动推荐写成已成立
- 把单样本写成全量可运营、长期稳定成熟
- 把条件推进写成自动切换或默认解锁
- 把文档齐备写成产品闭环已落地

### 4.3 需挂账项
必须继续挂牌，不得硬写完成：
- 未验证池能力
- 证据不足项
- 冲突待解项
- 规模化 / 跨项目 / 复杂图谱 / 深度影响分析等高阶项

推荐口径：
- `候选能力`
- `条件评估中`
- `需补证据`
- `未验证`

## 5. 口径边界

### 5.1 已实现
含义：
- 功能、对象或流程已存在且可用

限制：
- 不等于已通过真实样本验收

### 5.2 已验证
含义：
- 至少 1 条真实任务样本满足最小通过判定

要求：
- 必须附通过 / 不通过判定
- 必须附证据锚点

### 5.3 可运营
含义：
- 仅限已覆盖范围内可持续执行

要求：
- 必须同时声明未覆盖范围

禁止：
- 写成全量 / 长期 / 规模化可运营

## 6. 回退条件
出现任一项时，文档口径必须回退为：`未验证 / 需补证据 / 条件评估中`

触发回退的典型条件：
- 主链断裂
- 审批门禁失效
- Run 版本漂移
- 执行证据不足
- Retro 不完整
- 口径越界
- 回归失败或复核发现冲突

## 7. 最小回写单元模板
每条可写结论至少包含：
- **结论**
- **证据锚点**
- **覆盖范围**
- **未覆盖范围**
- **回退条件**

固定规则：
- 缺少任一项，不得写成“已成立”
- 证据冲突时，优先回退，不得硬保留旧口径

## 8. 对主计划收口与后续治理的约束
- 第五阶段主计划关账前，truth / ADR / phase 文档只能按本文规则跟随式更新
- 后续实现层若新增高阶自动化设想，只能挂牌为候选能力，不得回写为本阶段已成立事实
- 文档治理必须始终服从真实对象链、真实产品面、真实证据链与真实回沉闭环，不得反向凌驾于主线之上
